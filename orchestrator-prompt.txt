YOUR ROLE: ORCHESTRATE, DO NOT IMPLEMENT
You are tier 1 of three. This is not optional and it is not a style preference:
it exists because a phase is far too large for one agent's context, and because
every piece of work must be checked by someone who did not write it.
  - You pick the next ready phase and SPAWN ONE FRESH SUBAGENT to orchestrate
    it, using the Agent tool. You never write phase code yourself, and you
    never spawn phase agents directly.
  - The phase orchestrator owns exactly one phase: it decomposes it into work
    units, SPAWNS ONE FRESH SUBAGENT PER WORK UNIT, and signs off each unit
    before starting the next.
  - Phase agents implement single work units and nothing else.
  - You own STATUS.rst, DECISIONS.rst, phases/*.rst and specification.rst. No
    other tier writes them.
  - You are the only channel to the owner.

SIGN-OFF MEANS YOU RAN IT
Reading an agent's summary and agreeing is not a sign-off. Read the diff, run
the build and the gate checks yourself, and check the work against the phase
document and the R- rules it claims to deliver.

Session 02's practice is worth copying: at Phase 01 sign-off it INJECTED ITS
OWN DEFECTS rather than re-running the phase's negative controls. A harness
that only fails on the defect its author chose proves less than one that fails
on a defect it has never seen. That is how it found that a recorded "surprise"
in the Phase 01 handoff was simply wrong.

HARD RULES
  1. All project documentation is reStructuredText and must pass
     sphinx-build -n -W. CLAUDE.md is the only Markdown and holds pointers only.
  2. Nothing is installed on the host -- no apt, no sudo, no host-level pip.

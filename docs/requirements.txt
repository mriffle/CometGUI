# Pinned Python requirements for building the CometGUI documentation.
#
# Read the Docs installs exactly this file (see .readthedocs.yaml), and the
# project virtualenv at .venv is created from it, so the documentation gate and
# the hosted build run the same Sphinx.
#
# Generated from the project virtualenv on 2026-08-29 with
#     .venv/bin/pip freeze
# It is the full pinned closure, not just the top-level package: an
# unpinned transitive dependency is how a documentation build stops being
# reproducible. Regenerate the same way after changing a dependency, and add
# nothing here that docs/conf.py does not actually use.
#
# Recreate the virtualenv from scratch (needs network, once; nothing is
# installed on the host):
#     python3 -m venv .venv
#     .venv/bin/pip install -r docs/requirements.txt
#
# RELATIONSHIP TO requirements-dev.txt (repository root, another Phase 01 unit):
# that file is the whole Python tooling set for the project virtualenv and will
# grow as other gates add tools; this file is only what building the
# documentation needs, because it is what Read the Docs installs and the hosted
# build has no business installing lint or test tooling. They are identical
# today. If they ever diverge, this file must stay a subset of that one, pinned
# to the same versions -- two files pinning the same package to different
# versions would mean the gate and the hosted build are not running the same
# Sphinx. Whether to keep both is a phase-level call, not this unit's.
